# UX round: Team settings, account and auth (SET-)

Scope: settings shell and nav, Members + invite, API tokens, Git, Backups (destinations), Notifications, Updates, Dashboard domain, instance Security (mTLS), Profile, Security/2FA, project settings, auth screens (setup, login, 2FA challenge, CLI sign-in), destructive confirmations.

Screens looked at: fresh `ux-round/before/{api-tokens,alerts,backup-settings,cli-sign-in}-light.png`; older `site-retake/raw/{team-invite,git-providers,two-factor,updates,mtls,dashboard-domain,setup}-light.png`. No screenshot existed yet for x-profile, x-team, x-project-settings, so those were judged from source (`pages/settings/team.tsx`, `pages/projects/settings.tsx`).

## Laravel Cloud first (primary reference)

Laravel Cloud's settings are small and consistent. Every pattern below comes from the flows I opened.

- **One settings layout, text-only nav, cards with a grey header band.** Org settings is a top tab with a 7-item left nav (General, Access, Billing, Invoices, Notifications, Integrations, API tokens). Every card has a grey header band (title, one-line description, sometimes "Learn more") and white rows with the label and description on the left and the control on the right. [Settings flow](https://mobbin.com/flows/9f40a127-2794-4bbf-b07d-fe3ba81e94d0), [environment settings](https://mobbin.com/flows/eca009e6-ea0b-4020-916f-bf87cbbc8217). Our shell already looks like this (direction §5.12), so we only need to fix the details below.
- **Account settings are separate from org settings.** The avatar opens your own pages (General, Security, Source control, Organizations, Notifications). "Security" appears only once, under the account. [2FA setup flow](https://mobbin.com/flows/7417fb88-3f6e-46b1-8676-a0bca99567a9)
- **Security page: password is a row, not a form.** "Reset password: We'll email you a secure link · Send link". 2FA is a toggle row that opens a numbered two-step dialog (QR code / Setup key tabs, then the code). [same flow](https://mobbin.com/flows/7417fb88-3f6e-46b1-8676-a0bca99567a9)
- **Inline invite.** The Members card starts with one line: email field, role dropdown (Developer by default) and "Send invite". A pending invite appears straight away in the member list with an "Invite pending" chip, and its ⋯ menu has Resend invite and Revoke invite. A toast confirms. [Inviting a teammate](https://mobbin.com/flows/af0dc37e-e905-4c59-a1f1-7df4fbb3b866), [Removing an invitation](https://mobbin.com/flows/eda2435c-399b-4ba7-812c-39a579b11ba9)
- **API tokens.** The empty state is a centred "No API tokens yet · New API token". Creating a token opens a right sheet with only two fields: name and expiry ("After 6 months · Nov 6, 2026"). Each token is a small card: name, a scope summary chip ("Full access"), "Never used", and a footer line "Expires Nov 6, 2026". [Creating an API token](https://mobbin.com/flows/64cf02c8-9d28-4dab-aeb3-b672894c2a49), [sheet](https://mobbin.com/screens/699b61dc-6a3f-40d5-925b-2402a60673f2)
- **Integrations.** A connection is one row: logo, name, "Added just now", and an outline-red Disconnect button on that row. There is no separate danger list. [Connecting to Slack](https://mobbin.com/flows/7575b321-49e4-4fbd-bd52-3767e37ea358)
- **Notifications are configuration only.** One master toggle, the channel picker, then one toggle per event type, with the floating "Unsaved changes · Reset · Save" bar. The page has no list of open problems. [Updating notification settings](https://mobbin.com/flows/e34dd97d-a19d-444a-b6fe-4cd652a1fc17)
- **Destructive dialogs name the object and what is kept.** The "Danger" card has a red title and an outline-red "Delete application" button. The dialog shows the object as a chip ("ASMobbin · staging"), states what is NOT deleted ("Attached resources will not be deleted…"), and asks you to type the handle. A toast confirms afterwards. [Deleting an application](https://mobbin.com/flows/399dd16e-4e7d-4af6-a422-d4ab9d0d1b7b), [Deleting an environment](https://mobbin.com/flows/d63b174c-2afd-4962-8537-41cca4cd934b)
- **Sign-up is a split screen.** The form is on the left and a product picture is on the right. Our setup page already does this. [Onboarding](https://mobbin.com/flows/93a93e48-c570-4843-8780-d78b2da20a42)

## 1. Current state

- **Works:** the shell (search, grouped nav, one sentence under the title, cards) is in line with Laravel Cloud, Vercel and Linear. The mTLS Off/Check/Require option cards, the Dashboard domain hero ("localhost · No certificate") with its lock-out recovery command, the Updates hero with server cards, the invite sheet's multi-email field with a "Send 2 invitations" count, and the setup split screen are all good (mtls, dashboard-domain, updates, team-invite, setup). The project delete dialog already uses typed confirmation and handles the final backup (`pages/projects/settings.tsx`).
- **Two pages are both called "Security"** (Account → Security for password/2FA/passkeys, and This launchroom → Security for certificates/audit log). Each has a shield or lock icon, both show up in the nav at once, and search and breadcrumbs repeat the name (api-tokens, mtls, two-factor).
- **API token rows show raw ability keys** as badges (`read`, `env:read`, `secrets:read`, `data:transfer`; `pages/settings/api-tokens.tsx` TokenRow), and nothing identifies which token string a row belongs to. The CLI sign-in page shows seven permission checkboxes at once (cli-sign-in), and the create-token dialog uses the same list.
- **Notifications opens with 10 full-width "Open now" problem rows**, each with a "Look" link, before any setting (alerts). Configuring the page means scrolling past an inbox.
- **The Git page repeats every connection in a "Danger zone" list at the bottom** (6 Disconnect/Remove rows that mirror the 6 cards above; git-providers). The Security page opens with a permanently expanded 3-field password form, which is the least-used control on the page (two-factor).
- **Small things:** the Updates hero says "You're up to date" next to "Never checked" (updates). The backup destination donut is a full blue ring when only one kind of data exists, so the colour carries no meaning (backup-settings, `features/backups/destinations-section.tsx`). The older dashboard-domain shot has no breadcrumb; check that again in the fresh run.

## 3. Recommendations (ranked by impact ÷ effort)

### SET-1: Give the two "Security" pages different names
- **Problem:** Account → Security and This launchroom → Security sit in the same nav with near-identical icons. Search, breadcrumbs and help copy can't tell them apart.
- **Change:** rename Account → Security to **"Sign-in"** (password, two-factor, passkeys; Vercel calls it Authentication, Linear "Security & access"). Rename This launchroom → Security to **"Audit & certificates"**. Keep the routes. Update the page descriptions, the search drafts' `target` labels/hints, and any copy that says "Settings → Security" (grep for it, e.g. notifications copy "Action needed on the Security page" refers to the *app* Security page and stays).
- **Files:** `features/settings/settings-layout.tsx` (labels, `descriptions`), `features/settings/settings-index.ts`, `pages/settings/security.tsx`, `pages/settings/instance-security.tsx` (Head titles).
- **Evidence:** [Laravel Cloud account Security](https://mobbin.com/flows/7417fb88-3f6e-46b1-8676-a0bca99567a9), [Vercel Authentication](https://mobbin.com/screens/fe7d7e6e-ad12-48be-bc7f-d3e6ec6297c7), [Linear settings nav](https://mobbin.com/screens/f5906fed-ff32-4d80-b48d-063c19d2b844)
- **Effort:** S. **Docs:** docs/08-dashboard-ux.md §1 (settings groups list), docs/design/direction.md §5.12.

### SET-2: Token rows show one plain-language scope and what identifies the token
- **Problem:** rows list raw ability keys (`env:read`, `secrets:read`) as badges and can't be matched to a token string.
- **Change:** replace the badge list with one summary chip: "Full access" (every available ability), "Read only" (`read` only), "Deploy" (the default set), or "Custom · 4 permissions" with a tooltip listing `vocabulary.ApiAbility[...].label`. Show `Last used …` and put "Expires Nov 6, 2026" (or "Never expires") in muted text; keep the amber ⚠ when soon. Add a non-secret **hint** (`lr_…a1b2`, the prefix + last 4) stored at creation and shown in mono beside the name. This needs a `hint` column on `api_tokens` filled in `CreateApiToken` and exposed on `ApiTokenData`. It is not secret, but keep it out of logs anyway (docs/09 rule 4 is about the full value).
- **Files:** `pages/settings/api-tokens.tsx` (TokenRow), `features/api-tokens/ability-fields.tsx` (export `abilitySummary()`), `app/Data/Api/ApiTokenData.php`, the token-creation Action + a migration.
- **Evidence:** [Laravel Cloud token card](https://mobbin.com/flows/64cf02c8-9d28-4dab-aeb3-b672894c2a49), [OpenAI keys list](https://mobbin.com/screens/ee609751-3afe-401a-a0e4-ad1feed88da5), [Resend keys](https://mobbin.com/screens/babeaba9-a955-4e22-b1d3-c386d5ab37f6)
- **Effort:** S for the summary, M with the hint. **Docs:** docs/16-api-and-cli.md §1.3 (token list fields).

### SET-3: Access presets on CLI sign-in and Create token; checkboxes only under "Custom"
- **Problem:** the CLI approval (cli-sign-in) and the create dialog show 7 checkboxes with a sentence each. Approving a terminal means reading a permission matrix.
- **Change:** in `AbilityFields`, add a segmented control above the list: **Deploy** (today's `default` set, preselected) · **Read only** · **Everything** (all `available`) · **Custom**. Under the control, one line in plain words says what the choice allows ("Can deploy and change variables. Can't read secret values."). The checkbox list expands only for Custom. Abilities the role can't grant stay disabled with the existing reason. On `pages/cli/login.tsx`, keep the code card. Move "Stays signed in for" next to Team as a compact row so Approve sits above the fold at 1440×900.
- **Files:** `features/api-tokens/ability-fields.tsx`, `pages/settings/api-tokens.tsx` (CreateTokenDialog), `pages/cli/login.tsx`.
- **Evidence:** [OpenAI create key (All/Restricted/Read only)](https://mobbin.com/screens/d65a26a6-4f95-44e3-836f-f6bc2e14d543), [Snowflake token "Single role (recommended)"](https://mobbin.com/screens/8898e20e-5698-4d63-9fc0-8f14778ca614), [GitHub authorize screen](https://mobbin.com/screens/1080a459-b0e3-4d13-b344-53969f6ca16c)
- **Effort:** M (frontend only; presets derive from `team.abilities` flags). **Docs:** docs/16-api-and-cli.md §1.3 (CLI device sign-in page), design-system §13.9 if the segmented+custom pattern becomes a named pattern.

### SET-4: Notifications page is configuration; open problems become one summary row
- **Problem:** 10 "Open now" rows (up to 3 lines each, "Look" link) come before "Where we tell you". The page is an inbox that happens to contain settings (alerts).
- **Change:** replace `OpenAlerts` with one row at the top: a status glyph + "10 problems are open" + "Show" linking to where alerts already live (Activity filtered to open alerts, or the alerts sheet, whichever docs/15 §3.6 names). With none open, "Nothing needs you right now" (muted, ✓ glyph) or omit the row. If a list stays, cap it at 3 single-line rows ("server-3 is offline · 19 days") with "+7 more". Rename "Look" to a row chevron.
- **Files:** `pages/settings/notifications.tsx` (OpenAlerts).
- **Evidence:** [Laravel Cloud notifications](https://mobbin.com/flows/e34dd97d-a19d-444a-b6fe-4cd652a1fc17), [fal notification preferences](https://mobbin.com/screens/dc1fcc97-dfb4-4c6d-8d6d-2c085da7c0c7), [Apollo notifications](https://mobbin.com/screens/6269e0e8-2df2-4d71-b32a-9985683c1b48)
- **Effort:** S. **Docs:** docs/08-dashboard-ux.md (Notifications page section) and docs/15 §3.6 if it currently specifies the open list on this page.

### SET-5: Git: remove the page-wide Danger zone; disconnect lives on each connection
- **Problem:** 6 connection cards are followed by 6 matching Disconnect/Remove rows (git-providers). The list doubles the page length, and the action is far from its object.
- **Change:** delete the `SettingsCard title="Danger zone"` block. Put "Disconnect…" / "Remove setup…" in each `GitConnectionCard`'s ⋯ menu (or as the outline-red button on unfinished setups), behind the existing `ConfirmPopover` with the same consequence copy ("Services from it stop receiving pushes and can't build until it is connected again."). Name the affected services when known ("api and web stop receiving pushes").
- **Files:** `pages/settings/git.tsx`, `features/git/git-connection-card.tsx`.
- **Evidence:** [Laravel Cloud Slack row Disconnect](https://mobbin.com/flows/7575b321-49e4-4fbd-bd52-3767e37ea358), [Vercel sign-in method row ⋯](https://mobbin.com/screens/fe7d7e6e-ad12-48be-bc7f-d3e6ec6297c7), [Laravel Cloud invite ⋯ Revoke](https://mobbin.com/flows/eda2435c-399b-4ba7-812c-39a579b11ba9)
- **Effort:** S. **Docs:** docs/design/direction.md §5.12 currently says "destructive actions live in a final Danger zone card". Add: "…for the page's own subject; items in a list are removed from their own row or ⋯ menu".

### SET-6: Sign-in page: status rows first, forms on demand
- **Problem:** the page opens with an always-expanded current/new/repeat password form. 2FA and passkeys, the parts that tell you whether you're safe, sit below the fold.
- **Change:** order **Two-factor** (On/Off badge as today) → **Passkeys** (rows with "Added … · Last used …") → **Password** as one row: "Password · Changed 3 months ago" (or "Set") + "Change…" opening a dialog with the three fields. Keep recovery codes as a row inside the 2FA card.
- **Files:** `pages/settings/security.tsx`, `features/account/manage-passkeys.tsx`, `features/account/passkey-item.tsx` (last used, if stored). The password change goes into a small dialog component in `features/account/`.
- **Evidence:** [Laravel Cloud Security rows](https://mobbin.com/flows/7417fb88-3f6e-46b1-8676-a0bca99567a9), [Vercel Authentication](https://mobbin.com/screens/fe7d7e6e-ad12-48be-bc7f-d3e6ec6297c7)
- **Effort:** S–M (needs `password_changed_at` for the age; omit the age if not stored). **Docs:** docs/design/direction.md §9.14 ("Profile, Security, Appearance: settings rows").

### SET-7: Members: inline invite line + pending invites in the member list
- **Problem:** inviting one person opens a full-height sheet with four big role tiles (Owner first). Invites appear in a separate "Invited" card. With 1–2 people, the page is mostly empty around one button.
- **Change:** at the top of the members card (when `canManageMembers`), add one line: email input · role select (Developer default, roles ordered Viewer → Developer → Admin → Owner, each with its `summary` in the menu) · "Send invite". Keep the sheet as "Invite several…" for bulk paste. Render invitations as rows in the same list with an "Invited · expires in 6 days" chip and the existing ⋯ (Send again / Revoke). Toast "Invite sent to …". Optional: a small "2FA" chip per member (needs `twoFactorEnabled` on the member Data, visible to admins only).
- **Files:** `pages/settings/team.tsx` (TeamSettings, InvitationRow, InviteSheet), `App\Data\Teams\*` if the 2FA chip is added.
- **Evidence:** [Laravel Cloud inviting a teammate](https://mobbin.com/flows/af0dc37e-e905-4c59-a1f1-7df4fbb3b866), [Tailscale users with Invited chip](https://mobbin.com/screens/173a8b50-ee42-4a92-a6a6-d1b728c3e9fc), [Vercel members (inline invite, 2FA chip)](https://mobbin.com/screens/ef2f4dd6-54a5-4a53-b954-2a59e9f9e8e2)
- **Effort:** M. **Docs:** docs/design/flows.md §16 ("invitations in a sheet" becomes "inline invite, sheet for several").

### SET-8: One typed-confirm pattern that shows the object and what is kept
- **Problem:** the project delete dialog explains everything in prose (services, environments, volumes, final backup). Server removal and other deletes each build their own dialog (`features/moves/typed-confirm.tsx` exists but lives in a feature).
- **Change:** promote `typed-confirm` to `components/patterns/typed-confirm-dialog.tsx` with slots: **object chip** (icon + name + env/server), **Goes** (bullet list: "3 services in 2 environments, with deployments, variables and domains"), **Kept** (muted list with ✓: "Snapshots in Dev S3", "Data volumes for 7 days"), the existing final-backup checkbox, and "Type `shop` to confirm". Use it for project delete, server removal, account delete, and team delete if it exists. Toast after success.
- **Files:** new `components/patterns/typed-confirm-dialog.tsx`; `pages/projects/settings.tsx` (DeleteProjectDialog), `features/servers/fleet-card.tsx` / server settings delete, `features/account/delete-user.tsx`, `features/moves/typed-confirm.tsx` (reuse).
- **Evidence:** [Laravel Cloud delete application](https://mobbin.com/flows/399dd16e-4e7d-4af6-a422-d4ab9d0d1b7b), [Laravel Cloud delete environment](https://mobbin.com/flows/d63b174c-2afd-4962-8537-41cca4cd934b), [Databricks delete workspace](https://mobbin.com/flows/bc755123-52ac-4bfa-8dc3-e969bb03e0fb)
- **Effort:** M. **Docs:** docs/design-system.md §13.9 (add "Typed confirm" pattern next to ConfirmPopover).

### SET-9: Token creation as a two-field sheet with expiry shown as a date
- **Problem:** the create dialog asks for name, lifetime ("90 days") and 7 abilities at once. The lifetime doesn't say when the token stops working.
- **Change:** with SET-3's presets, the dialog becomes name · expiry select whose options read "90 days · Feb 14, 2027" · access preset. After creation, keep the show-once view but add the install/login hint for CI ("Set `LAUNCHROOM_TOKEN` in your CI").
- **Files:** `pages/settings/api-tokens.tsx` (CreateTokenDialog), `features/api-tokens/ability-fields.tsx` (`lifetimeLabel`).
- **Evidence:** [Laravel Cloud new token sheet ("After 6 months · Nov 6, 2026")](https://mobbin.com/screens/699b61dc-6a3f-40d5-925b-2402a60673f2), [Plane create token](https://mobbin.com/screens/bd570e9d-fbe1-4920-a989-4b6eec788afd), [Hex workspace token](https://mobbin.com/screens/608a5c2f-1a62-4dac-a69b-08076a0dec38)
- **Effort:** S. **Docs:** none beyond SET-3.

### SET-10: Settings replace the app sidebar rather than stacking a second nav (larger, optional)
- **Problem:** in `/settings/*` the app sidebar (≈256 px) and the settings nav (≈200 px + search) sit side by side. Content starts around x=570 at 1440 px, and two "current" highlights compete (Settings in the sidebar, the page in the settings nav).
- **Change:** at ≥1024 px, settings routes render the sidebar in a "settings" mode: "‹ Back to projects" at the top, then the settings groups (with the search field) in place of the app items, the team switcher and user menu kept. Phones keep today's drill-down list. Project settings keep their in-page nav (they are inside a project).
- **Files:** `components/settings/settings-shell.tsx`, `components/settings/settings-nav.tsx`, the app sidebar component (`components/app-sidebar.tsx` or equivalent), `features/settings/settings-layout.tsx`.
- **Evidence:** [Vercel team settings sidebar](https://mobbin.com/screens/d94fb15f-481e-4da4-bca3-520c9fe66516), [Linear "Back to app"](https://mobbin.com/screens/fc41ba13-34f5-429c-8f96-d37e18311c2d), [Plane workspace settings](https://mobbin.com/screens/bd570e9d-fbe1-4920-a989-4b6eec788afd)
- **Effort:** L. **Docs:** docs/08-dashboard-ux.md §1 (Settings), docs/design/direction.md §3 shell + §5.12, design-system §13.9.

### SET-11: Backups destination: no single-slice donut
- **Problem:** a destination with one kind of data draws a full blue ring around "47 MB latest copy". The colour carries no meaning, which breaks the "colour only with meaning" rule (backup-settings).
- **Change:** render the `Donut` only when `items.length > 1`. Otherwise show the number in the card's stat position (`47 MB` in `type-title`, "newest copy" muted), the way Laravel Cloud shows plain values in rows.
- **Files:** `features/backups/destinations-section.tsx`.
