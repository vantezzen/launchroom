# 07: Data model

Postgres. Conventions:
- **IDs**: `bigint` primary keys internally, plus a public, prefixed ULID (`public_id`, e.g. `prj_01J…`, `svc_…`, `dpl_…`, `srv_…`) used in URLs, APIs and launchroomd protocol. Prefixes make IDs self-describing in logs and support requests.
- **Tenancy**: every tenant-owned table has `team_id` (denormalised where useful) for scoping and policy checks.
- **JSON settings**: grouped settings live in `jsonb` columns cast to **laravel-data** objects (typed, validated, versioned). This avoids 60-column god tables and still gives types. Anything we query or constrain on gets a real column.
- **Enums**: PHP backed enums, stored as strings.
- **Secrets**: encrypted with the envelope scheme ([09](09-security.md)) and hidden from serialization by default.
- `morphMap` enforced (`Relation::enforceMorphMap`) for any polymorphic relation.

## Entity overview

```
User ─< TeamUser >─ Team ─┬─< Server ─< ServerEnrollment
                          │     └─< NodeStateVersion
                          ├─< GitHubApp ─< GitHubInstallation ─< GitHubRepository (cache)
                          ├─< Project ─┬─< Service ─< Connection (service→service)
                          │            ├─< Environment ─┬─< ServiceInstance ─┬─< Deployment ─< DeploymentStep
                          │            │                │                    │        └─< LogChunk
                          │            │                │                    ├─< Domain
                          │            │                │                    ├─< Volume
                          │            │                │                    └─< Placement (replica slot → server)
                          │            │                ├─< EnvironmentRevision
                          │            │                └── CanvasLayout
                          │            ├─< Variable ─< VariableTarget
                          │            └── ProjectKey (wrapped DEK)
                          ├─< DaemonTask
                          ├─< BackupDestination ─< Backup
                          ├─< ApiToken (Sanctum)
                          └─< AuditEvent
```

## Laravel-data objects (examples)

- Settings casts: `BuildSettings`, `DeploySettings`, `ScalingSettings`, `HealthcheckSettings`, `EnvironmentTriggers`, `ServiceSource` (union: `GitSource | ImageSource | DatabaseSource`). Properties carry `#[ChangeAffects(none|route|restart|rebuild)]` and `#[Promotion(structural|environment_specific|never)]` ([06](06-variables-environments.md) §4, §6.2).
- Revision: `EnvironmentSpec { environment: EnvironmentMetaSpec, services: map<svc id, ServiceSpec { settings, variables, connectionVariables, sharedVariableIds, domains (by hostname), volumes }>, connections: map<con id, …>, sharedVariables: map<var id, VariableSpec> }`. A `VariableSpec` is `{id, key, type, version, exposure, ciphertext, layer, generated, references, connectionId}`: enough to resolve and to restore (Discard) without ever holding plaintext. Staged changes are `SpecDiff::between(lastApplied, current)` → `StagedChanges { items: ChangeItem[], services: map<svc id, ChangeEffect> }`.
- Protocol: `NodeState`, `WorkloadSpec`, `RouteSpec`, `TaskSpec` variants. These are validated against the JSON Schemas in `protocol/` by contract tests ([10](10-codebase-conventions.md)).
- Inertia props: `ProjectCanvasData`, `ServicePanelData`, `DeploymentData`, … These generate TypeScript types.
