launchroom measures two things without any setup:

- **Traffic** for every service with a public domain, measured where requests enter your servers
- **Resource usage** for every service and server

Both appear a minute after the data exists. Charts mark every deploy so you can see what a release changed.

## Where to find them

A project's **Analytics** tab has two views. **Traffic** shows requests, errors, blocked requests and paths (see
[Analytics](/docs/observability/analytics)). **Resources**, described here, shows CPU, memory, latency and bandwidth.
Switching between the two keeps the range and the service you picked.

- **Analytics → Resources**: one environment at a time (production, staging, a preview), all services together or
  one service. Pick a service in the service menu or the Services list.
- **A service**: **Analytics** in the service panel's tab row, the node menu and ⌘K ("Analytics of web") open the
  project's Analytics filtered to that service: Traffic when it has a domain, Resources otherwise.
- **Server page → Resources**: CPU, memory, disk and network of that machine, plus the traffic it served if it has the
  "Serve traffic" role.

Resources charts have three ranges: **Hour**, **Day** and **Week**, starting on Day. They refresh on their own while the page is open. Click a point on a chart to open the logs of that moment, or only their errors.

## Request metrics

Every server with the "Serve traffic" role runs Caddy, which handles HTTPS for your domains. For each request, Caddy hands launchroomd a short record: host, method, path, status, duration and sizes. launchroomd sums them per route and minute and sends only these per-minute totals to the dashboard. The paths feed [Analytics](/docs/observability/analytics).

Requests and the error rate are in Analytics → Traffic; latency and bandwidth are in Resources. The totals give you:

| Metric | What it means |
|---|---|
| Requests | Requests per second over the chosen range |
| Error rate | Server errors (5xx) out of all requests. 4xx responses count as client errors |
| Latency p50 and p95 | Median and 95th percentile response time |
| Bandwidth | Bytes sent to clients per second |

Latency is kept as a histogram, so percentiles stay correct when several servers serve the same domain or when you look at a whole week.

### What never leaves Caddy

Before a record leaves Caddy, launchroom removes the client's IP address and port, the query string, every request and response header (cookies and credentials included) and TLS details. Only the referrer's host and one word from the user agent ("bot", "Mozilla" or nothing) remain for [Analytics](/docs/observability/analytics). launchroomd never sees who visited, and nothing per request is stored. Plain-HTTP requests only redirect to HTTPS and are not counted. Requests for hosts launchroom doesn't route are dropped.

<Callout type="info" title="Workers and databases">
Services without a public domain (workers, cron jobs, databases) have no request metrics. Their Resources view shows CPU and memory only.
</Callout>

## Resource usage

launchroomd samples every server and every container once a minute:

- **Per service**: CPU (in cores) and memory. Filtered to one service, the charts draw one line per replica when it runs several.
- **Per server**: CPU, memory and disk usage in percent, and network received and sent.

The servers overview shows system load across all your servers. Each server page shows its own charts and the services running on it. See [Servers](/docs/servers/add-a-server) for the server page itself.

## The Resources view

The top row has a card for **CPU** and **Memory**, and for services with public traffic also **Latency p95** and
**Bandwidth**. Each card shows:

- the value for the range
- the change against the previous period ("+12%"). Only latency is coloured, because a drop is always an improvement.
- sparklines for the top services, with the rest summed as "Other"

Select a card to see its full chart below. Under the chart, the **Services** list shows each service's CPU, memory and
p95. Click a service to narrow the view to it.

Earlier versions had a Metrics tab on the project and in the service panel. Their old links still work and open
Resources with the same range and service.

## Deploy markers

Every time chart of a service, project or server has a tick for each deployment in the range. Failed deploys are red. Hover a marker to see the service, the short commit SHA and the outcome, and click it to open the deployment. If latency jumps right after a marker, open that deployment, compare it with the previous one or [roll back](/docs/projects/canvas-and-services).

## How long metrics are kept

| Resolution | Kept for |
|---|---|
| 1 minute | 48 hours |
| 10 minutes | 30 days |
| 1 day | 1 year |

Older data is rolled up automatically, so the Week view loads fast and the database stays small.

## Alerts on metrics

The same numbers drive the built-in alert rules: high error rate, high CPU or memory and nearly full disks. Thresholds are set per team. See [Alerts](/docs/observability/alerts).
